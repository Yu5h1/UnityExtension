## 成員總覽

同一件事「把值存進 PlayerPrefs」有兩層，儲存形狀不同、互不相通：

| 層 | 型別 | 位置 | 儲存形狀 | 誰驅動 |
|---|---|---|---|---|
| UI 綁定 | `Preferences<T>`、`PlayerPreferences` | `Packages/common/Runtime/Component/` | 一個 KEY 一包 JSON，值全為字串 | uGUI 控件 |
| UI 綁定 | `DataView : IDataView` | `Packages/common/Runtime/Data/DataView.cs` | 上述 JSON 的記憶體形態 | — |
| UI 綁定 | `ValuePortAdapter<T,TValue>` 與 Toggle／Slider／InputField／TMP_InputField 實作 | `Packages/common/Runtime/Adapter/`、`Packages/UI/Runtime/Adapter/`、`Packages/Plugins/TMP/` | — | 控件轉接 |
| UI 綁定 | `ValuePort`（MonoBehaviour）及其子類 `OptionSet` 系列 | `Packages/common/Runtime/Data/ValuePort.cs`、`Component/OptionSystem/` | — | 自身即 port，單向（E4） |
| 型別化單值 | `PlayerPrefValue<T>`、`IPlayerPrefsSerializer`、`PlayerPrefsSerializer`（XML） | `Runtime/PlayerPrefsAdvanced.cs` | 一值一 key；int／float／string／bool 用原生 API，其餘走序列化器 | 程式碼 |
| 型別化單值 | `PlayerPrefJsonSerializer` | `Packages/common/Runtime/Data/` | 可替換 `PlayerPrefValue.Serializer`（全域靜態） | — |
| 型別化單值 | `ObservablePref<T> : ObservableValue<T>` | `Runtime/ObservablePref.cs` | 同上，加 `changed`／`init` UnityEvent | 程式碼或 Inspector 事件 |
| 型別化單值 | `PlayerPrefObject<T>`、`PlayerPrefBoolObject` | `Packages/common/Runtime/Data/` | ScriptableObject 包一個 `ObservablePref`，跨場景共用 | 資產 |
| 應用範例 | `AudioVolumePrefs` | `Packages/common/Runtime/Component/` | 以 `ObservablePref` 寫死 bgm／sfx／voice 三個音量與一個開關 | 靜態屬性 |

## UI 綁定層

### 架構

```text
PlayerPrefs                      一個 KEY 存一整包 JSON
   ↕ ToJson / TryParseFromJson
DataView : IDataView             string→string，key 比對不分大小寫
   ↕ ReadFrom / WriteTo
IValuePort                       Core MVVM 契約，值一律字串
   ↑ Preferences.ResolvePort 三段解析
   ├─ 物件本身是 IValuePort          ValuePort MonoBehaviour、OptionSet
   ├─ IAdapterShell.adapter          ToggleAddon 等 UI_Adapter 殼
   └─ AdapterFactory<Component>      原生控件無殼，執行期建純 C# Adapter
```

### 綁定流程

`Awake` → `OnInitializing` → `BindAll()`：解析全部 port → 缺欄位以控件目前值補上 → `WriteToBindings()` 把存檔寫回控件 → `BindTo(current)` 監聽變更。變更經 `DataView.Changed` → `_changed` 事件 → `SaveOnChanged` 時寫盤。順序本身是程式碼規則，由 csharp-core.md 擁有。

port map 為 per-instance `Dictionary<Object, IValuePort>`，壽命跟 Preferences 走；`UnbindAll` 清空，`OnDestroy` 呼叫它。

### 可綁控件

| 控件 | Adapter | 值格式 |
|---|---|---|
| `Toggle` | `ToggleAdapter` | `"true"`／`"false"`（讀入也接受 `"1"`） |
| `Slider` | `SliderAdapter` | `float.ToString()`，current culture |
| `InputField` | `UI_InputFieldOps` | 原字串 |
| `TMP_InputField` | `TMP_InputFieldOps` | 原字串 |
| `OptionSet` 系列 | 自身 | 選項的 `ToString`（`Object` 取 `name`） |
| `Dropdown`、`TMP_Dropdown`、`Scrollbar` | 無 | `IDropDownOps` 非 `IValuePort`，被靜默略過 |

可綁與否以登錄表為準：`AdapterFactory<Component>.Adapters` 中介面可指派給 `IValuePort` 的具體型別清單。不另外維護清單。

新增控件：仿 `ToggleAdapter` 寫 `ValuePortAdapter<TComponent,TValue>` 子類，註冊方式依 csharp-core.md *Register adapters safely*。`Preferences` 不需改。

### 擴充點

`Preferences<T>` 的 virtual：`KEY`、`TryLoadCurrent`、`SaveToPlayerPrefs`、`IsValidToSave`（目前無呼叫者）。

`UserDataView` 覆寫載入與存檔，把多組 `DataView` 以換行串接成多使用者資料，`KEY` 只存最後使用者。它依賴 `DataView.ToJson` 的扁平格式，改格式時必須一起遷移。它存了 `Password` 明文，違反下方約束。

## 型別化單值層

- `PlayerPrefValue<T>`：`key` + `defaultValue`，讀取時無 key 回傳預設值。複雜型別走 `PlayerPrefValue.Serializer`，預設 XML，可全域換成 `PlayerPrefJsonSerializer`。
- `ObservablePref<T>`：`SetValue` 值不同才寫入並觸發 `changed`；`Init(useDefault)` 以存檔值（或預設值）觸發 `init`，讓啟動時套用設定可以只在 Inspector 接事件完成。
- `PlayerPrefObject<T>`：多個場景共用同一個設定值時，以資產參照取代場景物件。
- `SetValue` 不呼叫 `PlayerPrefs.Save()`，由 Unity 在正常結束時寫盤。

## 設計決策

- **key 來源為 GameObject 名字（B1）**：2026-05-06 使用者決定，便利優先，脆弱模式可接受，真遇到問題再加安全機制。已知脆弱：改名後舊 key 成孤兒；Unity 預設名（`Toggle`）重名互相覆寫；改名無編譯期提示；名字不含父層路徑，大場景碰撞機率上升。
- **原生控件無殼綁定**：Adapter 是純 C# 類別，由工廠在執行期產生，不要求在控件上加元件。`ToggleAddon` 等 MonoBehaviour 殼保留為方法擴充用途，與綁定是兩條獨立路徑。
- **`SelectableAdapter` 不依賴**：使用者判斷意義不大，可能淘汰；本功能不假設它存在。
- 密碼、token 等秘密不進任何一層：PlayerPrefs 為明文。

## 風險待驗證

2026-05-07 實作完成時列出的驗收項目，未留下是否已驗證的紀錄：

- IL2CPP build 後，`[AdapterRegistration]` 反射註冊與 `[Preserve]` 建構子存活。
- 控件被 Destroy 後 port 仍在 map 內；`Unbind` 需走 Unity 的 `== null` 比較。
- 同一 Toggle 同時被殼與工廠包裝時 listener 重複，寫入次數倍增。
- 同一 Toggle 放進兩個不同 Preferences，listener 各自獨立。
- 重啟後控件顯示上次儲存值；既有實作 `IValuePort` 的 MonoBehaviour 仍能綁。

## 弊端評估

- **兩層並存且不相通**：新需求不知道選哪層；同一個設定若 UI 用綁定層、程式碼用 `ObservablePref`，會存成兩個 key。
- **無編輯期驗證**：`TypeRestriction(typeof(Component))` 只擋非 Component；不可綁、重名都要到執行期才發現，且多半靜默。
- **每次變動都寫盤**：Slider 拖曳時每幀 `PlayerPrefs.Save()`；WebGL 為同步寫 IndexedDB。
- **只在 Awake 綁一次**：之後 Instantiate 的面板需手動 `BindAll()`。
- **綁定層消費端拿字串**：套用設定要自己 parse，無型別化讀取、無 Reset API；型別化層則沒有 UI 綁定。
- **`AudioVolumePrefs` 放在 common 卻寫死音訊 key**：是應用範例而非通用元件。
- **單例一型一份**：兩組獨立設定需兩個子類別。

## 改善方向

依成本由低到高，未排程：

1. 移除 E3 警告與 E5 的 `print`。
2. E1／E2：`ToJson` 改用 `JsonUtility` 的 entries 格式，載入先試 entries 再退回扁平格式；Slider 值改 `InvariantCulture`。同步檢查 `UserDataView`。
3. 編輯期驗證（原 A1 方案，傾向採用）：自製 drawer 在拖入時同時接受「直接 `IValuePort`」與「登錄表有對應 Adapter」，拒絕其餘；並標出重名項目。可再加 `CONTEXT/` 選單「綁定選取的控件」，掛在 Preferences 元件上。
4. B1 的安全機制候選：啟動時檢查重名並 `LogError`；可選的 key 覆寫欄位；改名時掃描受影響的 Preferences。先做 3 的重名檢查，觀察碰撞頻率再決定其餘。
5. 存檔節流：變動只標 dirty，於延遲或 `OnApplicationPause`／`OnApplicationQuit` 寫盤。
6. 補 Dropdown 的 `IValuePort`（D3）。
7. 兩層收斂（D5）。

## UI Toolkit 適用分析

**給 `com.yu5h1.uitoolkit` 實作用。common 不實作 UI Toolkit 端。**

### 為何現有路徑無法直接用

- UI Toolkit 控件是 `VisualElement`，不是 `UnityEngine.Object`：放不進 `_bindings`，也不在 `AdapterFactory<Component>` 的鍵空間。唯一的 Component `UIDocument` 對應多個控件，而 `ResolvePort` 是一物件一 port。
- `UIDocument` 每次 `OnEnable` 重建 `rootVisualElement`，元素參照失效；`Preferences` 只在 Awake 綁一次。

### 可直接重用

`IValuePort`／`IDataView`（Core，引擎無關）、`DataView`、`Preferences` 的載入存檔與 `current`、綁定三步驟（補預設 → 寫回 → 監聽）。

### 有利條件

值控件皆實作 `INotifyValueChanged<T>`，一個泛型 port 即涵蓋 Toggle、Slider、SliderInt、TextField、DropdownField、EnumField 等。key 可取 `BindableElement.bindingPath`（UXML `binding-path`），脫離名字依賴，agent 只改 UXML 文字即可完成綁定。

### 建議形狀（D4）

`uitoolkit` 新增掛在 `UIDocument` 旁的元件：參照一個 Preferences，於 `OnEnable` 查詢帶 `bindingPath` 的值元素、包成泛型 port、跑綁定三步驟，`OnDisable` 解綁。生命週期歸 UIDocument 擁有者，`Preferences` 不需認識 UI Toolkit。

common 需提供：

1. 非泛型介面（例如 `IPreferences`）暴露 `current`，讓元件能以序列化欄位參照任一 `Preferences<T>`。
2. 把綁定三步驟抽成單一 port 的共用操作，兩條路徑共用，避免規則分岔。

### 需先驗證

- `bindingPath` 在 runtime 可讀，UXML `binding-path` 會填入它。
- 各控件值的字串化須與 uGUI 版一致（`EnumField` 名稱或值、`DropdownField` 文字或索引），否則同一份存檔在兩種 UI 間不相容。
- 替代方案：Unity 6 runtime data binding 以 `DataView` 作 `dataSource`。值全為字串，非字串控件皆需 converter，字典路徑支援未確認；目前不建議。

## 待討論決策

- **D1 JSON 格式遷移**：改 entries 格式並保留舊格式讀取（建議），或維持扁平格式改寫跳脫與解析。影響 `UserDataView`。
- **D3 Dropdown 的值**：選項文字（改文字即失聯）或索引（改順序即錯位）。建議文字，與 `DropdownField.value` 及 `OptionSet` 的字串化一致。
- **D4 UI Toolkit 綁定形狀**：上節「UIDocument 旁元件 + common 提供 `IPreferences` 與單 port 綁定」（建議），或讓 `Preferences` 認得「一物件多 port」並自行重綁。
- **D5 兩層分工或收斂**：維持兩層並由 skill 的選用表分流（現況）；或讓 `DataView` 的單一欄位可被 `ObservablePref` 式的型別化存取取代，讓 UI 與程式碼讀同一個 key；`AudioVolumePrefs` 是否移出 common 一併決定。
