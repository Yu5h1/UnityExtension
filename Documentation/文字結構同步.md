# 文字結構同步

> 設計方向：先完成 Edit Mode 的指定階層同步；Component 作為綁定入口，Scene View 作為檢視介面，Runtime 分階段加入。
>
> 上層 [Agent friendly workflow](Agent%20friendly%20workflow%20Yu5h1Lib.UnityExtension.md) 擁有格式、既有方案採用及術語擴充評估；本文件擁有同步行為與驗收。實作進度見 [handoff](../handoff.md)，本文描述預定行為。

## 系統階層與關係

```text
Yu5h1Lib.UnityExtension
└─ Agent 文字工作流
   └─ 文字結構同步
      ├─ 根物件 Component：來源文件、目標與管理範圍
      ├─ 共用核心：解析、驗證、引用解析、差異計算
      ├─ Editor 同步服務：接收完成標記、排程、同步紀錄與回報
      ├─ Editor 套用端：修改 Unity 物件、Undo、保存狀態
      └─ Runtime 套用端：後續加入執行期實例更新

Agent → 文件＋完成標記 → Editor 同步服務 → 共用核心 → Editor 套用端
Unity 物件 → Hierarchy／Inspector／Scene View → 人工檢視與調整
同步結果 → Editor 顯示＋Agent 可讀回報
既有格式／框架 → 經採用評估後接入上述責任
```

共用核心不依賴 Editor 視窗或檔案監聽。Editor 與 Runtime 各自提供目前物件的可比較狀態，消費相同的差異結果；是否需要介面或獨立套件，依採用評估及第二個實際案例決定。

## 目標與範圍

Agent 修改可讀文字，完成一輪編輯後發布標記，Unity 自動把有效版本同步到指定 GameObject 階層，並回報可追蹤的結果。人仍能使用原生編輯介面調整物件，人工修改不會被無聲覆蓋。

第一版處理已開啟 Scene 中的一個明確管理根、一份來源文件，以及子物件新增、刪除、改名、搬動、排序與 Transform。同步不依賴 Scene View 是否開啟；Scene View、Hierarchy 與 Inspector 都是檢視入口。

第一版範圍外：無限制雙向即時合併、複雜 Prefab overrides、Prefab Stage、跨 Scene 引用、蒙皮與 rig 編輯、獨立 Player 熱重載及多文件交易。這些能力依上層案例與採用評估逐步加入。

工作量：設計文件整理為小型；同步實作預估中型、架構影響為系統級，涉及物件身分、狀態所有權及 Editor／Runtime 生命週期。實作檔案與行數待選定既有方案後估算。此處為探索性設計，驗證需要 Unity 互動操作。

## 責任邊界

| 部分 | 擁有的責任 |
|---|---|
| 根物件 Component | 綁定來源文件及管理根，目標預設自身；提供可見的同步入口 |
| 共用核心 | 將文字轉成描述，驗證型別與引用，比較文件、上次同步及目前物件 |
| Editor 同步服務 | 接收版本完成標記、合併重複通知、排程、保存同步基準與回報 |
| Editor 套用端 | 在 Editor 主執行緒操作物件、組織 Undo、標示待保存狀態 |
| Runtime 套用端 | 後續處理執行期實例、狀態保留與失敗復原 |
| 類型註冊與格式 | 由上層工作流提供可用型別、欄位、引用與術語，不由同步服務另養一份 schema |

Component 保持薄層，排程與同步基準不全塞入其中。子物件不必各掛一個同步元件。穩定身分映射的保存方式須能支援重新載入，其具體位置列入待討論決策。

## 完成標記與同步流程

`mark 更動` 表示「這一版文件已完成，可以同步」。Agent 不必再逐項列出新增、修改或刪除；同步端從狀態比較產生變更清單。

1. Agent 編輯來源文件，可在同一輪修改多段內容。
2. 全部寫入完成後，發布含文件識別與版本識別的完成標記。版本需能核對實際內容，例如 revision 搭配內容 hash。
3. Editor 讀取對應內容快照；內容與標記不符時不套用，等待有效版本並回報原因。
4. 驗證完整文件、節點身分、型別與引用，取得目前 Unity 狀態及上次成功同步基準。
5. 計算變更與衝突。有效且無衝突、無待回寫差異時自動套用；第一版以整個管理根為單位，發現衝突或待回寫差異即停止該輪，避免只套用一半結構。
6. 套用前再次確認目標狀態仍符合比較基準；已被人或其他操作修改時重新比較，不使用過期差異。
7. 確認所有文件管理欄位與該版本一致後，更新基準並回報實際套用版本；待回寫、衝突或失敗都不推進成功版本。

檔案變動只作為喚醒線索，完成標記才是版本發布界線。標記可由旁檔或既有工具命令提供，實際傳輸方式尚未定案。MCP 可作選用觸發與診斷入口，不是逐物件同步的必要途徑。

同一目標每次只處理一輪同步。重複通知不重複修改；來源在套用期間出現新版時排入下一輪。回寫或 Undo 後也不因舊標記再次出現而立刻覆蓋人工操作。

## 物件身分與管理權

改名、搬動及排序應保留原物件與既有引用。純名稱路徑不足以辨識改名是否等於刪除再新增，不能依兩棵樹猜測身分。

候選方式是可讀且穩定的邏輯鍵與顯示名稱分開，或由明確改名／搬動操作維護映射；具體表示法與上層格式一起決定。Agent 不需操作 Unity instanceID。

同步只管理綁定根之內已納管的節點及欄位。同一物件／欄位不能同時被兩個同步根擁有；重疊綁定應在驗證時報錯。首次綁定既有階層先列出接管清單，由人明確接管，不能把同名物件自動視為已管理。

有效文件中移除已管理節點，才構成刪除候選。缺失檔案、解析錯誤、失效引用及未成功發布的內容都不代表刪除。刪除包含人工子物件的節點時報衝突，不連帶清除人工內容。欄位省略代表保留、解除管理或恢復預設，必須由格式契約明確定義後才可套用。

## 人工修改與同步基準

同步比較三份狀態：文件希望得到的值、Unity 目前的值、上次成功同步的值。第一版採文件管理指定欄位，人工調整先辨識，回寫由明確操作發起。

| 狀況 | 預定處理 |
|---|---|
| 文件改動，Unity 仍等於基準 | 套用文件變更 |
| Unity 改動，文件未改 | 保留人工值，標示待回寫並停止整輪；明確回寫或選擇採文件值後再同步 |
| 兩邊改成相同值 | 視為已一致，可納入成功基準 |
| 同一欄位兩邊改成不同值 | 報衝突，停止該輪，提供採文件值或保留並回寫的明確選擇 |
| 未管理欄位改動 | 保持原樣 |

結構刪除與搬動也須比較人工變更。明確回寫前再次核對來源版本，避免覆蓋 Agent 剛完成的新內容；回寫結果使用新版本，回報來源以避免通知迴圈。

同步基準、節點映射及成功版本需在 Editor 重新載入後可恢復。基準遺失或無法核對時進入重新對照流程，不把目前階層當作空場景重建。

## 套用、Undo 與結果

第一版一次成功同步對應一次 Undo 操作；Undo 後同步基準也需恢復或失效重算，不能仍宣稱最新版本已套用。成功代表目前場景已更新，保存到磁碟的狀態另外回報，避免把同步成功等同已保存。

預先驗證可預期錯誤，套用失敗時嘗試回復該輪變更。若無法完整回復，明確回報部分套用及受影響物件，暫停該根的自動套用，待重新對照；不得顯示成功。Undo 不能被假定能撤回任意自訂元件的外部副作用，這類型別需在後續擴充驗證更新能力。

Editor 與 Agent 應看到同一結果：目標、要求版本、已成功套用版本、處理狀態、變更摘要、文件位置與物件定位、衝突或失敗原因，以及是否已保存。Agent 能據此分辨等待、無變更、成功、待回寫、衝突與失敗。

## Edit Mode 與 Runtime

| 面向 | Edit Mode 第一版 | 後續 Play Mode／Runtime |
|---|---|---|
| 更新對象 | 作者編輯的場景階層 | 執行中的實例 |
| 共用部分 | 文件描述、驗證與差異語意 | 沿用同一核心 |
| 套用政策 | Undo、人工調整、場景保存 | 保留互動狀態、實例生命週期、復原能力 |
| 寫回作者資料 | 明確操作 | 必須另外明確發起 |
| 來源通知 | Editor 接收完成標記 | 由實際執行環境提供，不先假定可監聽本機檔案 |

第一版進入 Play Mode 時暫停作者場景的自動套用，回到 Edit Mode 後重新核對版本與目標。Runtime 以使用中的聊天面板作延伸案例，驗證更新外觀與內容時仍保留輸入、捲動位置及事件訂閱。Component 可作共同入口，但執行兩種模式不等於兩種套用政策已完成。

## 原型、驗收與遷移

先依上層採用評估選擇既有方案、薄層整合或必要自製部分。用同一個小型階層驗證，通過後再加既有組件／Prefab，最後以聊天面板檢查 Runtime 延伸。

| 案例 | 通過條件 |
|---|---|
| 根下建立 a／b／c／d／e，改 Transform | 完成標記後自動更新，Scene View 關閉仍可運作 |
| 改名、搬動、排序 | 原物件與測試用引用保持有效 |
| 重複發布同版本 | 零額外物件、零額外套用 |
| 半寫入、錯誤文件、失效引用 | 場景不變，回報可定位原因 |
| Inspector 與文件修改同一欄位 | 人工值不無聲遺失，衝突可明確解決 |
| 刪除含人工子物件的父節點 | 停止該輪並指出衝突 |
| Undo 與再次載入 Editor／Scene | 物件、基準、版本可重新一致，不重新套用舊通知 |
| 套用中發生失敗 | 回復或明確報部分套用，不推進成功版本 |
| Agent 讀結果 | 能核對目標與版本，區分同步成功及尚未保存 |
| 後續既有元件與聊天面板 | 核心 parser 不因業務元件而修改，重複同步不增加事件訂閱 |

原型先使用新建的專用根；既有 Scene／Prefab 接管另作一次明確遷移，不批次接管或改寫專案資產。

## 待討論決策

1. **身分表示與保存位置。** 推薦評估穩定邏輯鍵與顯示名稱分離；與明確操作方案比較改名、搬動、重新載入及文件可讀性，再選定映射保存方式。
2. **完成標記的具體形式。** 比較旁檔與既有工具命令，確認內容 hash、版本識別、重試及結果讀取的最小契約。
3. **省略欄位的語意。** 決定未寫欄位是保持原值、解除管理還是恢復預設；推薦以明確操作表達解除管理／重設，避免省略造成意外覆寫。

既有方案選擇、首個真實組合與 Markdown 必要收益由上層 [待討論決策](Agent%20friendly%20workflow%20Yu5h1Lib.UnityExtension.md#待討論決策) 擁有。完成這些決策後才能定實作契約；Runtime 的平台細節待延伸案例啟動時設計。
