# 指標互動與世界橋接

> 狀態：已實作（`com.yu5h1.common` 的算式、`com.yu5h1.uitoolkit` 的元件層）。
>
> 與其他文件的關係：運動核心與 `Drive` 契約見[運動系統](運動系統.md)；
> 執行狀態與下一步留在 [handoff.md](../handoff.md)。

## 系統階層與關係

```text
com.yu5h1.common                    純算式，不認識 UI
├─ SweptContact                     掃掠點對矩形碰撞
├─ PointerVelocity                  平滑化的甩出速度
├─ ViewportMath                     視域高度、面板↔世界雙向投影
├─ GroupDragLayout                  群組拖曳、角動量、慣性、避障擺放
└─ MathEx                           有限值與可用矩形的守衛

com.yu5h1.uitoolkit                 認識 VisualElement 的唯一一層
├─ ElementTarget                    把運動接到元素（實作 Drive 的介面）
├─ Gesture.LongPress                長按並抑制該次點擊
├─ World                            3D 與 UI 文件共用一個舞台
├─ ShakePlayer                      多元素抖動管理
└─ BottomSheet                      底部面板
    ↓ 依賴
com.yu5h1.animation                 運動核心
```

`common` 的算式收 `Rect`、`Vector2`、`Camera`，不收 `VisualElement`；
`uitoolkit` 負責把元素轉成那些型別再交給算式。政策一律以委派交還呼叫端。

## 摘要

這個系統把指標事件、UI 元素與 3D 場景接在一起。互動的形式只有一種：
**UI Toolkit 元件接事件**。3D 物件不直接參與互動 —— 由一個不繪製任何東西的元素代表它，
物件再被投射對齊到那個元素的矩形上。

## 問題與目標

- **問題**：指標互動的幾何（速度取樣、掃掠碰撞、投影、避障）與 UI 技術無關，
  但它們通常寫在控件內部，換一個介面就得重寫。
- **目標**：幾何與 UI 分離，幾何可在無面板的情況下驗證。
- **目標**：3D 與 UI 的對位是一組雙向換算，而不是兩套互動系統。
- **非目標**：不提供組合好的桌面控件；組合方式屬於消費端。

## 責任邊界

| 層 | 擁有 | 不擁有 |
|---|---|---|
| `common` | 幾何與運算 | 任何 UI 型別 |
| `uitoolkit` | 元素、指標事件、面板查詢 | 哪些元素算遮擋、什麼算撞到、誰住在哪 |
| 消費端 | 政策與組合 | 幾何與手勢的實作細節 |

跨界資料一律由呼叫端注入：`World.IsVisible` 的遮擋判斷與 `Reaction.Throw` 的命中判斷
都是 `Func<>`，由消費端提供。

## 設計

### 一條規則管所有手勢

**手勢屬於哪個元素，那個元素就同時捕獲指標、跑自己的計時器。**

拖曳一個圖示屬於那個圖示，拖曳背景屬於整片表面。把「捕獲」與「計時」分給不同元素，
失效方式是靜默的：擁有者收不到移動通知，或放手事件送到一個已經不在監聽的地方。
兩種都不編譯錯、不丟例外。

推論出兩條約束：

- `Gesture.LongPress` 必須掛在捕獲指標的那個元素上。掛在別處它對移動盲目，永遠不會放棄。
- 按住期間不得隱藏、停用或 reparent 任何元素。捕獲會無聲消失，放手事件永遠不來。

### 3D 如何加入

3D 物件由一個代表元素接手互動：

```text
代表元素（不繪製任何東西）
├─ 接指標事件、捕獲指標、跑手勢計時器
└─ 它的矩形 → World.TryPlace → 3D 物件該站的世界位置與尺寸
```

反方向由 `World.IsVisible` 回答「這個世界點被 UI 蓋住了嗎」，
`World.Fill` 則把 world-space 的 UI 文件縮放成剛好填滿相機視野，讓文件成為場景的一部分。

### 幾何為何獨立於 UI

`ViewportMath` 收的是一個矩形與一台相機。呼叫端傳什麼矩形進來 —— 元素的 `worldBound`、
一塊視口切片 —— 它都不需要知道。這讓投影、對位與遮擋的數學可以在沒有面板的情況下測試，
也讓同一組算式服務不同的 UI 技術。

### 掃掠而非取樣

指標一幀可以完整跨過一個小目標，只測端點會漏判。`SweptContact` 把整段位移當線段
對矩形裁剪，`Reaction.Throw` 的命中判定也走同一條路。

## 案例

- **可拖拉的桌面**：`GroupDragLayout` 給位置與慣性，`PointerVelocity` 取樣甩出速度，
  `Reaction.Throw` 接手飛行，`SweptContact` 判定撞擊。完整組合見
  `Packages/UIToolkit/Samples~/AppsMenu`。
- **3D 角色站在 UI 版面上**：代表元素定義位置，`World.TryPlace` 對齊角色，
  `World.IsVisible` 判斷戳擊是否被 UI 擋住，「哪些元素算擋住」由消費端以委派提供。
- **長按開啟選色**：`Gesture.LongPress` 的 `MoveTolerance` 設為 0，
  讓同一次拖曳可以從長按直接滑進選色；圖示拖曳則設為預設值，移動即放棄。

## 決策理由與替代方案

- **`BottomSheet` 保留呼叫端的元素命名**：控件需要 `sheet-layer`、`sheet`、`handle`、
  `scrim`、`sheet-title`、`sheet-kicker`、`sheet-scroll`、`sheet-close` 與 `hidden` class。
  缺少時在建構階段丟出並指名缺的是哪一個，而不是讓空參照在幾個互動之後才浮現。
- **`ElementTarget` 記住寫入值而不回讀**：UI Toolkit 的 style getter 回傳未解析的
  `StyleLength`，不是設進去的數字。它同時原樣快照靜止樣式，
  讓還原能放回「未設定」而不是明確的 0 —— 一旦 USS 對該屬性有意見，兩者算繪結果不同。
- **已排除：提供 `DraggableDesktop` 控件。** 寫完整的消費端範例後，
  沒有出現任何需要新抽象的地方；剩下的全是政策 —— 哪個矩形是障礙、app 住哪、
  什麼算丟進面板、多快算甩、長按代表什麼。那些正是不該進套件的東西。
