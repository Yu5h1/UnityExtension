## 系統階層與關係

```text
Unity 場景
├─ 粒子世界（本文件）：一份模擬、容量、步進與讀回
│  ├─ 實體：一次配置的一組粒子、約束、剛體群，以 handle 持有
│  ├─ 碰撞體：球、膠囊、方塊；由 Transform 推導形狀
│  ├─ 介質：區域、密度、流速
│  └─ 擴充階段：子步驟內與步後的掛勾點
│     └─ 擴充行為：介質狀態、游動、抓取、錨定、Bounds、睡眠……
├─ 粒子來源（宿主元件）：決定生成什麼、何時生成；向世界配置實體
└─ ParticleSolver：世界每個固定步驟呼叫一次
```

世界擁有模擬資料與容量；粒子來源與碰撞體向世界登記，不直接持有模擬資料。撰寫用的 profile 與來源元件的公開型別在第 2 階段另寫；本文件只規定它們與世界之間可觀察到的行為。

## 定義

粒子世界是場景中一份獨立的粒子模擬：它持有粒子、約束、剛體群、碰撞體與介質，每個固定步驟推進一次，並讓粒子來源在任何時候安全地配置、釋放、重置自己的實體。

## 目標

- **為誰服務**：BonghuoVR 的捕撈表演（目前唯一的消費者）。它在 Unified-Solver 上為了 singleton、自動登記、無法刪除粒子、新增時全部重置等缺點，修改了第三方程式並加了許多繞道；本規格把那些繞道換成世界本身的保證。
- **情境**：
  - 場景裡的世界是明確的，不靠 singleton；世界、碰撞體、粒子來源不論誰先啟用都能正確登記（明確的世界（WORLD-01）、登記先後無關（WORLD-02））。
  - 捕撈多輪後粒子數與約束數不變：魚與網可以釋放、槽位可以重用（釋放與重用（WORLD-05））。
  - 執行中晚生成的水管或魚，不會把既有的網與魚拉回出生狀態（新增與釋放不擾動其他粒子（WORLD-06））。
  - 容量不夠時整批拒絕並說明需要多少、還剩多少，不會留下半張網（實體配置與容量（WORLD-04））。
  - 來源啟用就重生、停用就收起；收起、閒置、睡眠的實體不耗運算（來源的啟用與停用（WORLD-08）、閒置與睡眠不耗運算（WORLD-10））。
  - 勺斗依粒子的 layer 只擋魚、不擋網，重用後 layer 仍正確（每粒子資料（WORLD-11））。
  - 抓取、錨定、介質等擴充行為可以在子步驟內作用（擴充階段（WORLD-13））。
  - 抓網數量、剛體姿勢以非同步讀回取得，不讓 CPU 等 GPU（非同步讀回（WORLD-14））。
- **不在此目標**：
  - 撰寫用 profile 與來源元件的公開型別（第 2 階段）。
  - Edit 模式的模擬預覽：GPU 模擬不能倒帶；Edit 模式只顯示靜止佈局與 Gizmo。
  - Play 中重調已建立約束的材質（BonghuoVR 仍未決定是否需要）。
  - 質量語意（每顆粒子質量或整體質量）：留給第 2 階段的 profile。
  - 多個世界之間的交互作用：不同世界的粒子互不可見。
- **完成條件**：Motion package 的實作通過下方〈平台檢查〉全部項目，並在 Motion package 的測試場景中重現 BonghuoVR 網、魚、水管、勺斗情境，多輪循環下粒子數與約束數不變。
- **狀態**：2026-11-14 目標由使用者確認；尚無實作，目標未達成。

## 世界

### 明確的世界（WORLD-01）

- **規則**：世界是場景元件。沒有全域 singleton 或靜態 `Instance`。一個場景可以有多個世界，彼此獨立。
- **解析**：粒子來源與碰撞體以明確參考指定世界；未指定時，取場景中唯一**啟用中**的世界。沒有或有多個啟用中的世界時，報錯並寫出候選，不靜默挑一個；停用中的世界永遠不會被選中。
- **證據**：第三方 manager 的 singleton 搜尋包含停用物件且無排序，預放的停用 Rig 被先找到，導致第二輪 `ClothGenerator.Start` 索引例外（BonghuoVR `SolverManager本機依賴修正.md`）。
- **驗證**：PWORLD-CHECK-01。

### 登記先後無關（WORLD-02）

- **規則**：世界、碰撞體、粒子來源的啟用順序任意，結果相同：
  - 世界啟用時，接收所有已啟用且解析到它的碰撞體與來源。
  - 世界停用時暫停並保留登記（WORLD-09）；世界銷毀時釋放所有登記。
  - 任何時候另一個世界成為解析結果（例如原世界停用或銷毀後只剩它啟用），來源與碰撞體從原世界取消登記、釋放實體，改登記到新世界。解析失敗時維持原本的綁定。
  - 碰撞體停用時一定取消登記，世界不存在也一樣；重新啟用時一定重新登記。
- **記錄**：登記與取消登記預設不輸出記錄；世界提供詳細模式時才輸出。
- **證據**：消費端在 `Start` 快取舊實例不跟著換（Requirements.Unified-Solver 需求 1 證據 3）；碰撞體在 manager 為 null 時停用會保留已登記旗標，之後不再登記（第三方程式被修改的第 3 段）；每次開關都輸出含 stack trace 的記錄（`效能評估.md`）。
- **驗證**：PWORLD-CHECK-02、03。

### 登記在步驟邊界生效（WORLD-03）

- **規則**：配置、釋放、重置、碰撞體登記等變更，可以在任何時間呼叫；它們在下一個步驟開始時一起生效，絕不在步驟或子步驟中途生效。同一步驟前的多個變更依呼叫順序套用。
- **證據**：第三方求解器要求在 `FixedUpdate` 內新增，否則錯一步（`unified-solver.md` skill）。
- **驗證**：PWORLD-CHECK-04。

### 世界的啟用與停用（WORLD-09）

- **規則**：世界停用時暫停：不步進、不排任何 GPU 工作，粒子狀態保留。再次啟用時從保留的狀態繼續。銷毀時釋放全部資源。
- **證據**：已初始化的 manager 停用再啟用不會重新初始化，停用也不清粒子，語意不明（BonghuoVR `SolverManager本機依賴修正.md`、`物理表演改版計畫.md`）。
- **驗證**：PWORLD-CHECK-05。

## 實體與容量

實體是一次配置的完整單位：一組粒子，加上連結它們的距離約束與剛體群。一條魚、一張網、一條水管、一塊冰各是一個實體。

### 實體配置與容量（WORLD-04）

- **規則**：配置一個或一批實體前，先計算全部需求（粒子、約束、剛體群）並與剩餘容量比較：
  - 足夠時全部建立，回傳每個實體的 handle。
  - 不足時整批拒絕，不建立任何部分；錯誤寫明需要量與剩餘量。
  - 呼叫端明確要求「盡量建立」時，回傳實際建立的實體數，每個都是完整實體。
- **輸入檢查**：半徑 ≤ 0、反質量 < 0、非有限的位置或速度、約束兩端相同或越界時，整個請求拒絕並說明原因。
- **容量設定**：粒子、約束、剛體群、各類碰撞體、介質的上限是世界的設定；超過碰撞體上限時登記失敗並報錯，不靜默截斷。
- **跨來源原子性**：兩個來源在同一步驟前配置時，容量檢查依呼叫順序進行，先通過的保留容量，後面的看到扣除後的剩餘量。
- **證據**：容量滿時第三方 generator 拿到 −1 繼續建約束，留下半張網（需求 2）；碰撞體超過 64 被截掉；跨 emitter 預留不是原子操作（套件 handoff Known limitations）。
- **驗證**：PWORLD-CHECK-06、07。

### 釋放與重用（WORLD-05）

- **規則**：釋放 handle 後，該實體的粒子、約束、剛體群立即不再參與模擬與碰撞（自下一步驟起），容量歸還，之後的配置可以重用這些槽位。釋放同一個 handle 兩次不會出錯也不影響其他實體；已釋放的 handle 不能再讀寫。
- **多輪穩定**：同樣的生成與釋放循環重複任意次，已用容量回到相同數值。
- **證據**：第三方求解器只能新增、不能移除，`ResetSimulation` 清空全部，於是 BonghuoVR 改成先配置再重用（需求 1 證據 1）。
- **驗證**：PWORLD-CHECK-08。

### 新增與釋放不擾動其他粒子（WORLD-06）

- **規則**：任何配置、釋放、重置都只影響被指定的實體；其他實體的位置、前一位置、速度、約束狀態（含已斷）、剛體旋轉逐位元不變。
- **證據**：第三方求解器每次新增都把整份出生時的 CPU 快照蓋回 GPU，下網時魚被拉回、水管晚生成也一樣（需求 1 證據 2）。
- **驗證**：PWORLD-CHECK-09。

### 傳送與重置（WORLD-07）

- **規則**：
  - **傳送**：把實體的粒子移到新位置（或新姿勢）時，同時寫入位置與前一位置，速度設為指定值（預設 0）；不會因為只寫位置而產生 (新 − 舊)/h 的巨大速度。
  - **重置**：把實體回到配置時的靜止佈局（可指定新姿勢），速度歸零，已斷的約束恢復，剛體旋轉回到配置時的值。
  - 未指定靜止長度的約束，以配置當下粒子在模擬中的位置計算長度（ParticleSolver SOLVER-03）。
- **證據**：只寫位置會變成約 1500 倍的速度，擴充層因此同時寫位置與前一位置並歸零速度（套件 plan）。
- **驗證**：PWORLD-CHECK-10。

### 執行中更新約束參數（WORLD-16）

- **規則**：實體 handle 可以替換它所有約束的參數：靜止長度、柔度、阻尼與斷裂力，在下一步驟生效。約束的數量與連結的粒子不能改；數量不符時拒絕並報錯。位置、速度與已斷的狀態都不變，已斷的約束保持斷開。之後的重置使用新的參數。驅動器在互動 profile 改變後把新參數交給它的實體。
- **證據**：水管在播放中調彎曲軟硬；Unified-Solver 的繩子包裝在約束 buffer 中原地改寫自己那一段（套件 `SolverRopeParticles.cs`）。
- **驗證**：PWORLD-CHECK-18。

### 來源的啟用與停用（WORLD-08）

- **規則**：粒子來源啟用時重生它的實體（第一次啟用時配置，之後重置到生成姿勢）；停用時收起：實體保留容量但不參與模擬、碰撞與 GPU 運算，也不畫出來。來源銷毀時釋放它的實體。
- **場景載入**：場景載入時預設停用的來源，不需要額外的暫時啟用工具；第一次啟用時才配置，配置不擾動其他粒子（WORLD-06），所以晚配置是安全的。場景載入後才 Instantiate 的來源同樣適用。
- **證據**：預設停用的物件第一次啟用才加粒子，觸發全部重置；擴充層為此在載入時暫時啟用再收起，而載入後才 Instantiate 的物件仍未涵蓋（需求 4；套件 handoff Known limitations）。
- **驗證**：PWORLD-CHECK-11。

### 閒置與睡眠不耗運算（WORLD-10）

- **規則**：
  - 沒有任何參與模擬的粒子時（全部收起或尚未配置），步驟不排任何 GPU 工作。
  - 收起的實體不進入任何 kernel 的運算範圍。睡眠中的實體不進入求解器的預測、約束、碰撞形狀、剛體群、速度更新、介質與擴充的範圍，只放進鄰近結構當作不動的接觸對象（ParticleExtensions EXT-13）；睡眠由擴充行為標記，喚醒後從保留的狀態繼續。
  - GPU 工作量隨參與模擬的粒子、約束數增減，不隨已配置容量。
- **證據**：有收起的粒子時第三方求解器永不提早返回，每步約 242 次 dispatch；擴充層的睡眠仍跑完所有 kernel（`效能評估.md`；套件 plan）。
- **驗證**：PWORLD-CHECK-12。

## 每粒子資料與存取

### 每粒子資料（WORLD-11）

- **規則**：每顆粒子在配置時設定半徑、群組與分類（意義見 ParticleSolver）：
  - **半徑**：每顆各自設定；鄰近結構以最大半徑決定格子大小。
  - **群組**：配置時可要求「這個實體一個新群組」（實體內不互碰）或 0（與所有粒子互碰）；新群組由世界分配，釋放後可重用。
  - **分類**：32 位元。來源 GameObject 的 Unity layer L 對應分類位元 1 << L；碰撞體的碰撞對象 mask 是它自己的圖層遮罩設定（預設全部圖層）。重用槽位時分類隨新實體重新設定，不殘留前一個實體的值。
  - 三者都可在配置後由實體 handle 更新，於下一步驟生效。
- **證據**：第三方粒子結構只有自動分配的 phase，不能指定分類，也沒有空欄位，擴充層另開一份 layer buffer；半徑全域一個（需求 5；套件 plan）。
- **驗證**：PWORLD-CHECK-13；數值部分見 PSOLVE-CASE-14、16。

### 公開粒子範圍（WORLD-12）

- **規則**：實體 handle 公開它在世界中的粒子範圍（起點與數量）、約束範圍與剛體群索引，以及每顆粒子在佈局中的角色（例如網格的列與行、鏈的序號）。擴充行為、繪製與宿主程式透過 handle 取得，不需要反射或讀私有欄位。
- **證據**：第三方 generator 不公開 offset，擴充層與 BonghuoVR 以反射讀取三個私有欄位與 `_particleOffset`；cloth 配到的 phase 也要讀回才知道（套件 handoff Contract guarantees；需求證據）。
- **驗證**：PWORLD-CHECK-14。

### 擴充階段（WORLD-13）

- **規則**：擴充行為向世界註冊在具名階段，世界依階段與註冊順序執行：
  - **子步驟內**：在碰撞形狀之後、剛體群之前（ParticleSolver SOLVER-01 的順序中），可讀寫粒子位置；適合抓取、錨定、依 layer 的推出。
  - **步後**：所有子步驟之後，可讀寫粒子速度；介質受力（ParticleSolver SOLVER-17）在此。
  - 同一階段內依註冊順序執行；註冊時宣告會寫入的資料（位置或速度），兩個擴充在同一階段寫同一份資料時依註冊順序，不另外合併。
  - 擴充行為只處理參與模擬的粒子（收起、睡眠、已釋放的不在範圍內）。
- **證據**：第三方求解器沒有子步驟掛勾，擴充效果每步只跑一次，寫入的速度只維持約 1/30 步，layer 碰撞因此要求板子夠厚；執行順序靠 `DefaultExecutionOrder`（需求 5 證據 3；套件 plan；`unified-solver.md`）。
- **驗證**：PWORLD-CHECK-15。

### 非同步讀回（WORLD-14）

- **規則**：世界只提供非同步讀回：請求某些粒子、剛體群或擴充結果（例如抓到幾顆），結果在之後的某一幀送達，並標明它屬於哪一個步驟。也可以一次請求一段連續槽位的位置，段內其他實體的槽位照原樣包含在內。世界本身不做同步讀回，也不在每步自動讀回剛體群。
- **剛體姿勢**：剛體群的繪製在 GPU 上直接讀取模擬結果組矩陣；需要在 CPU 使用姿勢時以非同步讀回取得。
- **證據**：第三方求解器每步同步讀回剛體 buffer 且不能關；抓網每輪約 10 次同步讀回（套件 handoff Known limitations；`效能評估.md`）。
- **驗證**：PWORLD-CHECK-16。

### 碰撞體（WORLD-15）

- **規則**：碰撞體是場景元件，形狀由 Transform 推導：
  - 球：球心 = 位置，半徑 = 0.5 × lossyScale 的最大分量。
  - 膠囊：沿本地 Y 軸；半徑 = 0.5 × max(scale.x, scale.z)；半段長 = max(scale.y, 半徑) − 半徑；兩端點 = 位置 ∓ up × 半段長。
  - 方塊：中心 = 位置，半邊長 = lossyScale × 0.5，軸 = right、up、forward。
  - 世界每步開始時讀取啟用中碰撞體的姿勢，並以上一步的姿勢計算表面速度（ParticleSolver SOLVER-14）；碰撞體以傳送方式移動時（例如重設位置）可標記傳送，該步表面速度為 0。
  - 同一類型的處理順序是登記順序。
- **證據**：形狀推導沿用第三方碰撞體元件；表面速度是 BonghuoVR 的 layer 方塊碰撞體已示範、第三方求解器缺少的能力（套件 handoff）。
- **驗證**：PWORLD-CHECK-17。
